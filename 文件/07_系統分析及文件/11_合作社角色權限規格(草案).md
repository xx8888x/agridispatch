# 智農派工 合作社角色權限規格（草案，2026-10-15）

> **狀態**：草案，尚未實作。目前系統只有一種後台角色 `admin_tech`（科技後台管理員），合作社沒有自己的帳號、頁面與權限。
> **本文件的範圍**：定義合作社角色能看什麼、能改什麼；實作後同步更新 `03_認證與API安全規格.md`。
> **法規與契約**：標【待確認】的項目交由律師或主管機關確認，本文件不下法律結論。

## 1. 背景

- **合作社是法定雇主**：雇用工人、給付工資、辦理勞健保、安排並查核每日接送。
- **科技公司受委託代管系統**：依《營運委託暨技術代管協議》提供排程調度與計費系統。
- 因此，雇主責任範圍內的操作應由合作社執行；系統設定、帳號管理、金鑰等留給科技公司。

## 2. 角色

| 角色代碼 | 名稱 | 說明 |
|---|---|---|
| `admin_tech` | 科技後台管理員 | 現有，擁有全部權限 |
| `coop_admin` | 合作社管理員（新增） | 雇主責任範圍內的操作，詳見第 3 節 |

決議：
- **只做一級**：先只有 `coop_admin`，不分「管理員／勞務員」兩級。若日後需要（例如勞務員不能結算薪資），再拆權限，不影響本次設計。
- **單一合作社**：目前只有一個合作社，角色不帶「所屬合作社」欄位。若將來有多個合作社，所有資料表要加合作社欄位並依此過濾，屬另一個專案。

## 3. 權限矩陣

圖例：✏️ 可看可改　👁 只能看　⛔ 不可

### 3.1 雇主責任（合作社 ✏️）

| 範圍 | 操作 | 科技後台 | 合作社 | 對應頁面與 API |
|---|---|---|---|---|
| 工人名冊 | 新增、編輯、停用；查證件與工作許可效期 | ✏️ | ✏️ | `GET/POST/PUT/DELETE /api/workers` |
| 加退保 | 登錄勞健保、職保、就保的加退保與申報編號 | ✏️ | ✏️ | `/api/insurance/**`、保險登錄頁 |
| 出勤 | 補登、修正出勤；領班評核 | ✏️ | ✏️ | `/api/payroll/attendance`、`/api/evaluations/**` |
| 薪資 | 月結算、重新開放、薪資單、登錄實發 | ✏️ | ✏️ | `/api/payroll/months/**`、發薪結算頁 |
| 請假 | 核准、駁回、取消 | ✏️ | ✏️ | `/api/leaves/**`、請假審核頁 |
| 派工 | 確認出工名單、改派 | ✏️ | ✏️ | `/api/matching/**`、派工媒合頁 |
| 共享班表 | 開班、確認、取消 | ✏️ | ✏️ | `/api/rosters`（POST、confirm、cancel） |
| 收款 | 登錄尾款、補登發票號碼、作廢 | ✏️ | ✏️ | `/api/payments/**`（登錄類） |
| 密碼重設 | 重設**工人與農場主**的臨時密碼（忘記密碼時，核對身分後操作） | ✏️ | ✏️（不可重設管理員帳號） | `POST /api/auth/reset-password`、帳號與密碼管理頁 |
| 接送查核 | 登記每日接送 | — | ✏️ | 尚無功能，另列需求 |

### 3.2 只能看（合作社 👁）

| 範圍 | 說明 |
|---|---|
| 訂單與農場主資料 | 農場主聯絡電話可見（派工與現場聯絡所需）【待確認：個資法告知範圍】 |
| 營收、成本、利潤分流報表 | 唯讀 |
| 天候戰情、派工總覽 | 唯讀；切換天候情境屬科技公司操作 |
| 熟手標籤、工班評價 | 唯讀；暫停標籤的複核恢復仍由雇主（合作社）操作 |
| 工班合法化彙總 | 唯讀 |

### 3.3 不給合作社（⛔，留給科技公司）

- 帳號清單以外的帳號管理：新增或刪除管理員帳號、變更任何帳號的角色
- 作物基準、文宣 DM、系統設定
- LINE 官方帳號設定與推播（含方案行銷廣播）
- 重灌示範資料與所有 `/api/dev/**`
- 科技代管費（Take Rate）的計算設定

## 4. 個資可見範圍

| 資料 | 合作社 | 說明 |
|---|---|---|
| 工人薪資、出勤 | 可見全部 | 合作社是雇主，必須處理 |
| 工人證件號碼（居留證、護照） | 遮罩 | 沿用現有序列化遮罩，只顯示末幾碼；需要完整號碼時另案申請【待確認：個資法與合作社內部管理辦法】 |
| 農場主電話 | 可見 | 同 3.2 |
| 密碼雜湊、Token | 不可見 | 任何角色都不回傳 |

## 5. 科技公司與合作社的資料界線

- 科技公司（`admin_tech`）可看合作社帳務的**彙總**（營收、應收、代管費計算依據），用於計費與系統運維。
- 逐人薪資明細、證件號碼：科技公司以運維所需為限【待確認：委託協議的資料歸屬、查核權限與個資委外條款，由律師確認】。
- 在律師確認前，系統先維持現況（科技後台可看全部），確認後再依結論收斂 `admin_tech` 的可見範圍。

## 6. 實作計畫（核准後）

1. **角色**：`AuthContext` 新增 `ROLE_COOP = "coop_admin"` 與 `isCoop()`、`isAdminOrCoop()`；Token、`/api/auth/me`、帳號建立與 `GET /api/auth/accounts` 認得新角色。
2. **授權**：`AuthInterceptor` 的 `ADMIN_ONLY` 清單依 3.1 逐條改為「管理員或合作社」，3.3 的路徑維持僅管理員；Controller 與 Service 內的 `ctx.isAdmin()` 檢查同步檢視。
3. **密碼重設**：合作社只能重設 `farmer`、`worker_local`、`worker_foreign` 角色的帳號，不可重設 `admin_tech` 與 `coop_admin`。
4. **前端**：新增合作社登入頁與導覽（只列 3.1、3.2 的頁面）；後台頁面依角色隱藏選單與按鈕；`js/api-client.js`、Mock 與 Android 的頁面角色對應補上。
5. **測試**：對每個角色、每組 API 驗證允許與拒絕（含 403）；`AuthHardeningTest` 補密碼重設的角色限制。
6. **文件**：回寫 `03_認證與API安全規格.md` 第 3、5 節。
