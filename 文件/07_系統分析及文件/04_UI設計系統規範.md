# 智農派工 AgriDispatch — UI 設計系統規範

版本 1.0　2026-10-02　適用：`Software/demo/` 全部前端頁面（同步至 web、android）

## 0. 一句話

**不讓使用者思考。** 農民在田埂上用手機、戴著手套、太陽很大。每一個畫面只回答一個問題，只有一顆主要按鈕。

## 1. 為什麼要有這份文件

2026-10 評估時的量化結果（demo/，不含 vendor）：

| 頁面 | 色相 | 漸層 | emoji | 按鈕+連結 |
|---|---|---|---|---|
| 主網站 index.html | 12 | 17 | 209 | 88 |
| 科技後台 admin.html | 11 | 15 | 330 | 109 |
| farmer.html | 8 | 9 | 117 | 46 |

每頁都用了 8～12 種顏色、十幾個漸層、上百個 emoji，每個元素都在「喊」，結果沒有任何東西能被看見。共用 CSS 只有 90 行，其餘全部寫死在 HTML 裡的 Tailwind class，無法「改一處、全站生效」。

本規範對應的實作：`css/agri.css`（元件與 token）、`js/agri-theme.js`（共用 tailwind.config、demo 模式標記、圖示、toast、抽屜）。

## 2. 色彩：一主、一輔、一危、一外部

| 角色 | Token | 色值 | 只能用在 |
|---|---|---|---|
| 主色 | `--ad-primary` | Emerald #059669 | 主要按鈕、選中狀態、連結、品牌 |
| 強調 | `--ad-accent` | Amber #f59e0b | 金額、定金、倒數天數、購買／付款按鈕 |
| 危險 | `--ad-danger` | Red #dc2626 | 真正的錯誤、刪除、超時 |
| 外部 | `--ad-line` | LINE #06c755 | 只准 LINE 相關按鈕 |
| 中性 | `--ad-bg / surface / surface-2 / border / text / text-2 / text-3` | Slate 系 | 其他一切 |

**禁用**：purple、indigo、blue、cyan、pink、violet、fuchsia、rose、orange、lime。「角色用不同顏色區分」這個做法廢除——角色由標題文字與導覽內容區分，不是顏色。

預設深色（與現有頁一致）；`<html data-theme="light">` 可整站切亮色，元件不用改。前台（`AgriDispatch/`）的田間頁在手機／觸控裝置預設亮色、桌機維持深色，見第 10 節。

## 3. 字級：5 階

| Class | 大小 | 用途 |
|---|---|---|
| `.ad-display` | 32（手機 28）| 頁面唯一 h1 |
| `.ad-title` | 20 | 區塊標題 h2 |
| `.ad-heading` | 16 | 卡片標題 h3 |
| 內文（body） | 15 | 內文 |
| `.ad-caption` | 13 | 說明、標籤、meta |

字重只有 400／600／700。`font-black`（900）禁用。表單輸入框字級固定 16px（避免 iOS 自動縮放）。數字一律 `.ad-num`（等寬數字）。

## 5. 版面規則

1. **一個螢幕一顆 `--primary`**。第二重要的動作用 `--secondary`，其他 `--ghost`。
2. **表頭只有一條**（56px）。頁面標題放在內容區第一行，不另開一帶。LINE 綁定狀態用一個 `.ad-pill`，不用橫幅。
3. **導覽按角色**：農場主看「預約／訂單／工班／帳務」，移工看「今日／打卡／薪資／語言」，領班看「帶隊／打卡／薪資」，管理員看「戰情／訂單／工班／營收」。跨角色切換只在 demo 模式、收進右上角抽屜。
4. 可點擊目標 ≥ 44px（`--ad-tap`），手機主要按鈕 `--block`。
5. 陰影只有 `--ad-shadow` 一種，給浮層（toast、抽屜）用；卡片不加陰影。
6. 漸層禁用（含文字漸層）。動畫只有 `.ad-live`（即時連線中）一種。

## 6. 文案規則

- 按鈕：動詞開頭，≤ 6 字，不加括號、不加 emoji。「送出預約」「立即購買」「開始打卡」。
- 標題：一句一事，不用 ╳、・串接名詞。
- 下拉選項只放名稱；價格、說明放旁邊欄位或 `.ad-hint`。
- 不對使用者顯示技術字眼（Port、Webhook、Vue3、REST、API、JIT）。
- 數字給單位，單位用 `.ad-price__unit` 或 `<small>` 弱化。

## 7. Demo 與正式版的分界

- `agri-theme.js` 依 `AGRI_CONFIG.mode` 在 `<html>` 加 `is-demo` 或 `is-production`。
- 任何只給路演看的元素加 `data-demo-only`：示範導覽抽屜、免密提示、角色切換、「後端離線」提示。production 看不到。
- Pitch 內容（痛點、雙軌架構、產曆雷達、投資人數字）放 `brochure.html` / `legalize.html`，不放產品頁。

## 8. 載入順序（每頁 `<head>`）

```html
<script src="js/app-config.js"></script>
<script src="js/api-client.js"></script>
<script src="js/vendor/tailwindcss-3.4.17.js"></script>
<script src="js/agri-theme.js"></script>          <!-- 取代各頁 inline tailwind.config -->
<script src="js/vendor/lucide.min.js"></script>
<link rel="stylesheet" href="css/style.css">
<link rel="stylesheet" href="css/agri.css">
```

`<body class="ad-body">`。頁面若有手機底部導覽，再加 `ad-has-tabbar`。

### 預約表單三步（farmer.html）

- 表單用 `<ol class="ad-steps">` 分三步，每步一個問題：**做什麼**（作物、派工類別、面積）→ **什麼時候開工**（起工日、計價方式）→ **怎麼聯絡你**（姓名、電話、地點）。
- 計價方案從三張卡縮成一列 `.ad-seg`（label 包 radio，JS 切 `is-active`，底下一行說明跟著換）。方案值與後端一致：`early_bird`／`hourly_flex`／`turnkey`（舊版前端送 `flexible`／`lump_sum`，後端會回 400，選這兩種根本送不出單，已修）。
- 「現場小工頭」預設勾選「工人報到時直接聯絡我」，欄位收起；送單時由農場主資料帶入對口。取消勾選才展開帶隊人欄位。
- 「黑轉白四大保障」移到右欄報價卡下方，不佔表單路徑；法規文字逐字保留。
- **報價以後端為準**：右欄報價打 `POST /api/orders/calculate`（作物每分地標準工時 × 面積 × 方案時薪；早鳥 315、彈性 310、統包依作物費率 95 折；緊急救火至少 360），成立訂單時後端用同一套算法，所以畫面金額 = 成立金額（舊版前端用「人數 × 天數 × 8 小時 × 315」自算，與後端不一致）。人數與天數由系統依面積估出，農民可選填「每日工人數」（1～30）：**人數不影響總價，只決定編制與完工天數**（人愈多愈快完工）；不填就用系統估算，輸入框 placeholder 顯示「系統估 N 人」。指定的人數存在訂單 `requestedWorkers`，派工媒合以它為需求人數。預計完工日 = 起工日 + 預估天數（進位）。只有連不上後端的 demo 離線展示才用前端 `localQuote`（鏡像後端算法，作物參數取自 `SeedService`；後端調整作物工時或費率時要同步改 `OFFLINE_CROPS`）。
- `?pkg=<DM id>`：文宣 brochure.html「線上預約派工」與簡報 pitch.html 購買流程都帶 `?pkg=`。**工時包以文宣 DM 的標價為準**：表單鎖定作物、派工類別、面積與計價（只剩開工日、人數與聯絡資料要填），報價與建單都帶 `packageId`，後端取該 DM 的工時、價格、定金（`POST /api/orders/calculate` 與 `POST /api/orders` 皆支援），所以文宣標價 = 成立金額；管理後台修改 DM 價格，之後成立的訂單隨之改變。人數預設為 DM 建議編制（芒果 4、溫室 6、無人機 2、冷鏈 5），可改，只影響完工天數、不影響價格。頂端的「已帶入工時包」卡可按「自己填」解鎖，改回依作物與面積計價（訂單 `packageId` 清空）。作業地點只在 demo 模式帶示範地址。`?workers=`、`?category=` 可在 pkg 之後覆蓋（category 在鎖定時不套用）。
- 目前開放線上預約的工時包是 4 張標準 DM（對應表在 `OrderService.PACKAGE_SPECS`）：芒果 60 工時 18,900、溫室 120 工時 37,800、無人機 30 工時 25,200（牌價 28,800）、冷鏈 80 工時 25,200。管理後台自訂的其他 DM 尚未開放線上預約（回 400），要開放需補作物與派工類別的對應。離線展示用前端 `PACKAGES` 的固定價複本，DM 標準資料改了要同步改。

### 清理型改版與腳本（admin.html 頁籤）

- 大型頁面（admin.html 約 240KB）不逐段重寫，改用可重跑的清理腳本批次處理，再以「前後文字逐頁比對」確認沒改到內容：先在舊版擷取每個頁籤的文字（移除 emoji 後）、按鈕數、輸入框數、表格列數，改完用同一支腳本再擷取，兩邊必須相同（刻意改動的字除外）。
